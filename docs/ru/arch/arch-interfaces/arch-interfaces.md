# {heading(Основные интерфейсы)[id=arch_interfaces]}

Для работы с {var(sys5)} используются следующие типы интерфейсов:

* Графические интерфейсы (GUI).
* Командные строки (CLI).
* Программные интерфейсы (API).

В данном разделе будут рассмотрены основные интерфейсы, доступные для взаимодействия со стороны пользователей и администраторов {var(sys2)}.

## {heading(Графические интерфейсы)[id=arch_gui]}

### {heading(Портал самообслуживания)[id=arch_mcs_ui]}

Портал самообслуживания является основным графическим интерфейсом пользователей {var(sys2)} и используется для управления виртуальными ресурсами в рамках одного или нескольких проектов. Каждая учётная запись может иметь доступ к неограниченному количеству проектов. Роли пользователей, а значит и их доступ к функциям {var(sys2)} могут отличаться от проекта к проекту.

Условное обозначение: VK CP UI (или MCS UI, устаревшее).

Доступ к Порталу самообслуживания {var(sys2)} осуществляется при помощи веб-браузера по следующему адресу:

```txt
vkc.your_domain_name.ru
```

, где `your_domain_name.ru` — это доменное имя Заказчика {var(sys2)}.

Для входа в Портал самообслуживания используется любая персональная учётная запись пользователя {var(sys2)}.

### {heading(Портал администратора)[id=arch_sa_ui]}

Портал администратора является основным графическим интерфейсом администраторов {var(sys2)} и используется для управления основными настройками и административными функциями {var(sys2)}, а также ролями групп пользователей в проектах.

Вместо Портала администратора возможно использовать OpenStack CLI.

Доступ к Порталу администратора {var(sys2)} осуществляется при помощи веб-браузера по следующему адресу:

```txt
admin.your_domain_name.ru
```

, где `your_domain_name.ru` — это доменное имя Заказчика {var(sys2)}.

Для входа в Портал администратора используется учётная запись {var(sys2)}, для которой был выставлены роли с префиксом `sa_`. При настроенной интеграции с Active Directory (AD) может быть использована учётная запись из AD. Выдачу ролей для пользователей из AD можно автоматизировать штатными средствами Keycloak.

### {heading(Портал мониторинга)[id=arch_portal_monitoring]}

Портал мониторинга является основным графическим интерфейсом для мониторинга {var(sys2)}.

Условное обозначение: Zabbix.

Доступ к Порталу мониторинга {var(sys2)} осуществляется при помощи веб-браузера по следующему адресу:

```txt
monitoring.your_domain_name.ru
```

, где `your_domain_name.ru` — это доменное имя Заказчика {var(sys2)}.

В случае наличия интеграции с AD для входа в Портал мониторинга используется учётная запись Администратора {var(sys2)} из AD. В противном случае используется отдельная учётная запись администратора Zabbix.

### {heading(Портал логирования)[id=arch_opensearch]}

Портал логирования является основным графическим интерфейсом для просмотра журналов событий {var(sys2)}.

Условное обозначение: OpenSearch.

Доступ к Порталу логирования {var(sys2)} осуществляется при помощи веб-браузера по следующему адресу:

```txt
logs.your_domain_name.ru
```

, где `your_domain_name.ru` — это доменное имя Заказчика {var(sys2)}.

В случае наличия интеграции с AD для входа в Портал логирования может использоваться учётная запись Администратора {var(sys2)} из AD. В противном случае используется отдельная учётная запись администратора для доступа к Порталу логирования.

### {heading(Портал управления доступом)[id=arch_keycloak]}

Портал управления доступом является графическим интерфейсом администраторов {var(sys2)} для управления пользователями, группами пользователей и настройками защиты отдельных сервисов {var(sys2)}.

Условное обозначение: Keycloak.

Стандартные учетные записи {var(sys2)} создаются, удаляются и настраиваются именно через этот интерфейс (либо через API Keycloak). Кроме того, через данный интерфейс могут настраиваться различные аспекты доступа к {var(sys3)}, например, интеграция {var(sys2)} с AD в части учётных записей пользователей.

Доступ к Порталу управления доступом {var(sys2)} осуществляется при помощи веб-браузера по следующему адресу:

```txt
idm.your_domain_name.ru
```

, где `your_domain_name.ru` — это доменное имя Заказчика {var(sys2)}.

Для входа в Портал управления доступом используется стандартная учётная запись {var(sys2)}, имеющая соответствующие права доступа.

## {heading(Интерфейсы командной строки)[id=arch_cli]}

Для работы Пользователей {var(sys2)} использование командной строки не требуется.

Для администрирования {var(sys2)} может потребоваться использование следующих интерфейсов командной строки:

* SSH и Bash (выполнение команд после подключения к узлам {var(sys2)}).
* OpenStack CLI.
* Ansible.
* cURL.

<warn>

При расследовании инцидентов возможно потребуется дополнительно использовать следующие интерфейсы командной строки:

* Docker CLI.
* Kubectl.

</warn>

### {heading(SSH)[id=arch_ssh]}

Защищенный протокол для удаленного доступа к компьютерам, в том числе для подключения к узлам {var(sys2)}.

Базовый синтаксис для подключения к узлу {var(sys2)} (см. раздел {linkto(../../usage_administration/interfaces_access#deploy_host_auth)[text=%text]}):

{caption(Команда для подключения к узлу {var(sys2)})[align=left;position=above]}
```bash
ssh <ИМЯ_ПОЛЬЗОВАТЕЛЯ><IP_ХОСТА>
```
{/caption}

Описание параметров можно найти в документации на ОС, в которой будет использоваться SSH (см. [пример для Ubuntu](https://manpages.ubuntu.com/manpages/xenial/man1/ssh.1.html)).

### {heading(OpenStack CLI)[id=arch_openstack]}

Интерфейс командной строки для API-интерфейсов OpenStack.

По умолчанию OpenStack CLI развёрнут на узлах {var(sys2)} и не требует дополнительной настройки. При использовании локального OpenStack CLI может понадобиться установка зависимостей, см. раздел {linkto(../../usage_administration/interfaces_access#prerequisites_openstack_cli_software)[text=%text]}.

Базовый синтаксис см. в {linkto(../../cli_commands#cli_commands)[text=%text]}.

### {heading(Ansible)[id=arch_ansible]}

Интерфейс командной строки для развёртывания, конфигурирования и обновления компонентов {var(sys2)}.

Базовый синтаксис см. в [официальной документации](https://docs.ansible.com/ansible/2.9/user_guide/command_line_tools.html).

### {heading(cURL)[id=arch_curl]}

Инструмент командной строки, часто используемый для отправки HTTP-запросов. Поддерживает большое количество протоколов, в том числе HTTP-запросов к RESTful API.

{caption(Базовый синтаксис cURL)[align=left;position=above]}
```bash
curl [options / URLs]
```
{/caption}

Описание параметров см. в [официальной документации](https://curl.se/docs/manpage.html).

Пример использования см. в разделе {linkto(../../usage_administration/interfaces_access#interface_rest_api)[text=%text]}.

### {heading(Docker CLI)[id=arch_docker]}

Инструмент командной строки для управления Docker-контейнерами.

{caption(Базовый синтаксис Docker CLI)[align=left;position=above]}
```bash
docker [options] <COMMAND> [<ARGUMENTS>]
```
{/caption}

Описание параметров см. в [официальной документации](https://docs.docker.com/engine/reference/commandline/cli/).

### {heading(Kubectl)[id=arch_kubectl]}

Инструмент командной строки для управления кластерами Kubernetes с целью создания и управления кластерами.

{caption(Базовый синтаксис Kubectl)[align=left;position=above]}
```bash
kubectl [command] [<TYPE>] [<NAME>] [flags]
```
{/caption}

Описание параметров см. в [официальной документации](https://kubernetes.io/ru/docs/reference/kubectl/overview/).
