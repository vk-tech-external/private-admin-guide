## {heading(Определение статуса кластера Ceph)[id=ceph_managed_status]}

Перед выполнением любых операций с кластером Ceph проверьте состояние кластера с помощью команд `ceph status` или `ceph -s`.

{caption(Пример ожидаемого результата)[align=left;position=above]}

```console
   cluster:
    id:     91328958-a86a-4846-a8e6-49721f4ba611
    health: HEALTH_OK
 
  services:
    mon: 1 daemons, quorum csn001 (age 2d)
    mgr: csn001(active, since 2d)
    mds: cephfs:1 {0=csn001=up:active}
    osd: 2 osds: 2 up (since 2d), 2 in (since 2d)
 
  data:
    pools:   7 pools, 257 pgs
    objects: 24.59k objects, 191 GiB
    usage:   193 GiB used, 506 GiB / 700 GiB avail
    pgs:     257 active+clean
```
{/caption}

Случаи, при которых кластер будет иметь статус отличный от `HEALTH_OK`:

* Созданы пул, и группы размещения, но пиринг между OSD не установлен.
* Только что добавлен OSD в кластер или удален из кластера.
* Только что изменили CRUSH maps, и группы размещения мигрируют.
* В разных репликах группы размещения есть несогласованные данные.
* Группы размещения восстанавливаются прямо сейчас.
* Ceph очищает реплики группы размещения.
* У Ceph недостаточно емкости хранилища для завершения операций `backfill`.

## {heading(Определение группы размещения c ошибкой)[id=ceph_managed_pg]}

Группа размещения не обязательно неисправна или работает неправильно, если ее состояние отличается от `active+clean`. Длительное пребывание группы размещения в другом состоянии может указывать на то, что кластер Ceph не может выполнить самовосстановление. Состояния, сообщающие о наличии каких-либо ошибок:

* `unclean` — группы размещения содержат объекты, которые не были реплицированы желаемое количество раз. В нормальных условиях можно предположить, что эти группы размещения восстанавливаются прямо сейчас.

* `inactive` — группы размещения не могут обрабатывать операции чтения или записи, поскольку они ждут, когда OSD с самыми последними данными вернется в рабочее состояние.

* `stale` — группы размещения находятся в неизвестном состоянии, поскольку OSD, на которых они размещены, не отправляли отчеты в кластер монитора в течение определенного периода времени (определяется `mon_osd_report_timeout`).

Чтобы определить группу размещения с ошибкой выполните команду:

```console
# ceph pg dump_stuck [unclean|inactive|stale|undersized|degraded]
```

## {heading(Проверка использования OSD)[id=ceph_managed_osd_mon]}

Если OSD заполнен данными почти полностью, Ceph предотвращает потерю данных, гарантируя, что новые данные не будут записаны в OSD.

В правильно работающем кластере проверки работоспособности запускаются, когда OSD и пулы кластера достигают определенного процента заполнения:

* Порог `mon_osd_full_ratio` — по умолчанию равен 0,95 (или 95% емкости). Это число, выше которого записывать данные невозможно. 

* Порог `mon_osd_backfillfull_ratio` — по умолчанию равен 0,90 (или 90% емкости). Это число, выше которого операции `backfill` не будут запускаться. 

* Порог `mon_osd_nearfull_ratio` — по умолчанию равен 0,85 (или 85% емкости). При достижении 85% емкости запускается проверка работоспособности `OSD_NEARFULL`.

Чтобы проверить общее использование данных кластера и распределение данных между пулами, выполните команду `ceph df`.

{caption(Пример ожидаемого результата)[align=left;position=above]}

```console

hdd    700 GiB  506 GiB  191 GiB   193 GiB      27.63
TOTAL  700 GiB  506 GiB  191 GiB   193 GiB      27.63
 
--- POOLS ---
POOL                   ID  PGS  STORED   OBJECTS  USED     %USED  MAX AVAIL
glance-images           1   64  191 GiB   24.56k  191 GiB  30.31    440 GiB
cinder-volumes          2   32      0 B        0      0 B      0    440 GiB
vms                     3   64      0 B        0      0 B      0    440 GiB
cephfs_metadata         4   32   27 KiB       22  527 KiB      0    440 GiB
cephfs_data             5   32      0 B        0      0 B      0    440 GiB
manila-volumes          6   32      0 B        0      0 B      0    440 GiB
device_health_metrics   7    1      0 B        0      0 B      0    440 GiB
```
{/caption}

При проверке вывода команды `ceph df` обратите особое внимание на наиболее заполненные OSD. 

Если один из OSD переполнится, это может привести к сбоям в записях в его пул. Когда команда `ceph df` показывает, сколько места доступно для пула, она учитывает настройки, основываясь на самом заполненном OSD в этом пуле.

Чтобы убедиться, что не достигнут предел емкости, соотнесите число в столбце `%RAW USED` с коэффициентом `full_ratio` и коэффициентом `nearfull_ratio`.

Чтобы настроить пороги заполнения OSD, выполните команды:

```console
# ceph osd set-nearfull-ratio <float[0.0-1.0]>
# ceph osd set-full-ratio <float[0.0-1.0]>
# ceph osd set-backfillfull-ratio <float[0.0-1.0]>
```
Ошибки с заполненным кластером могут возникнуть из-за сбоя OSD. 

Когда OSD или узел хранит избыточный процент данных кластера, отказы компонентов или естественный рост нагрузки на узел могут привести к превышению коэффициентов `nearfull` и `full`. 

При тестировании устойчивости Ceph к сбоям OSD на небольшом кластере рекомендуется оставить достаточно свободного места на диске и рассмотреть возможность временного снижения коэффициентов OSD `full`, `backfillfull` и `nearfull`.

|`norebalance`
|Запрещает новые операции повторной балансировки

|`norecover`
|Запрещает новые операции восстановления. Если необходимо заменить диск OSD без восстановления группы размещения на другом OSD во время горячей замены дисков, установите `norecover`, чтобы запретить другим OSD копировать новый набор группы размещения на другие OSD

|`noscrub`
|Блокирует новые операции очистки. Если необходимо запретить scrubbing, например, для снижения накладных расходов во время высоких нагрузок, восстановления, операций `backfill` и повторной балансировки, вы можете установить `noscrub` и/или `nodeep-scrub`, чтобы запретить кластеру OSD scrubbing

|`nodeep-scrub`
|Блокирует новые операции глубокой очистки

## {heading(Последовательность перезапуска узлов кластера Ceph)[id=ceph_managed_status]}

1. Перед тем, как останавливать кластер Ceph, убедитесь, что он в работоспособном состоянии (статус кластера `HEALTH_OK` и все группы размещения в статусе `active+clean`). Для этого запустите команду `ceph status` на узле монитора.

1. Отключите кластер CephFS:

   ```console
   # ceph fs set cephfs max_mds 1
   # ceph fs fail cephfs
   # ceph status
   # ceph fs set cephfs joinable false
   ```

1. Установите флаги `noout` и `norebalance`:

   ```console
   # ceph osd set noout
   # ceph osd set norebalance

   ```
1. Остановите процессы Ceph и/или узел штатным образом.
