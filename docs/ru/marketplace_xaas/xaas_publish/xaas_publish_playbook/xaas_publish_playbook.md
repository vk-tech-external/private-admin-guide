# {heading(Публикация сервиса в Marketplace c помощью плейбука)[id=xaas_publish_playbook]}

Публикация сервиса в Marketplace осуществляется с помощью плейбука `ansible-openstack/playbooks/xaas-add-app-to-catalog.yml`.

Плейбук позволяет:

* Добавлять приложения, предоставляемые в дистрибутиве {var(system)}.
* Обновлять приложения в каталоге Marketplace — добавлять новые версии приложений и публиковать их взамен предыдущих.
* Публиковать приложения, добавленные в каталог с помощью плейбука.
* Сконфигурировать набор приложений для добавления в каталог Marketplace при установке {var(sys2)}.

Список доступных приложений и конфигурация содержaтся в файле `~/inventory/vkcloud/group_vars/vkcloud_control_plane/xaas-apps.yml`. 

У каждого приложения есть флаг `install`, который определяет, будет ли приложение автоматически добавляться в каталог во время установки {var(sys2)}. 

Поле `nexus_source` определяет, откуда брать дистрибутив приложения:

* `true` — скачивать с Nexus, адрес которого задан в переменной `xaas_nexus_repo_url`.

* `false` — искать файл дистрибутива в `xaas_distrs_path/catalog`, по умолчанию это `~/xaas/catalog`.

<warn>

Не изменяйте значение `nexus_source` в `xaas-apps.yml`. Дистрибутивы тех приложений, у которых значение `true`, поставляются в составе дистрибутива {var(sys2)}. Как правило, рекомендованные для загрузки в каталог Marketplace по умолчанию. Такие приложения изначально имеют значение `true` в параметре `install`.

</warn>

Чтобы включить другие приложения из списка для установки, настройте параметры:

1. В параметре `install` установите значение `true`.

1. Если значение параметра `nexus_source = false`, вручную добавьте дистрибутив приложения для установки в `{{xaas_distrs_path}}/catalog` (по умолчанию `~/xaas/catalog`). Файл дистрибутива должен иметь имя `<значение поля distr приложения из файла xaas-apps.yaml>.tar.gz`. Список приложений, устанавливаемых по умолчанию и доступ для скачивания дистрибутива предоставляется по запросу.

1. Опционально. Переопределите дефолтные значения параметров приложения `overrides.parameters` в `xaas_apps.yml`.

1. `promote` — `true`, если сразу после установки хотите опубликовать приложение (это можно будет сделать и позже через API).

1. `promote_spaces` — добавьте названия пространств, в которые будет публиковаться приложение.

<info>

Помимо загрузки приложений от {var(system)}, данный способ может использоваться для установки приложений, созданных самостоятельно или сторонними разработчиками. 

Для каждого поставщика потребуется создать отдельный файл с конфигурацией приложений для добавления в каталог Marketplace как `~/inventory/vkcloud/group_vars/vkcloud_control_plane/xaas-apps.yml`.

Если необходимо загрузить приложение другого разработчика, используйте предварительно зарегистрированного в системе поставщика (подробнее — в разделе {linkto(../../../xaas_instructions/xaas_vendor_index#xaas_vendor_index)[text=%text]}).
Если поставщик зарегистрирован во время выполнения плейбука, задайте дополнительные переменные. 

</info>

Чтобы добавить и опубликовать сервис в Marketplace c помощью плейбука:

1. Выполните вход на деплой-ноду по SSH (подробнее — в разделе {linkto(../../../interfaces_access#deploy_host_auth)[text=%text]}).

1. Запустите Ansible playbook:

   ```console
   $ cd ~/inventory/vkcloud 
   $ ansible-playbook -i vkcloud.yml --diff -e @/home/centos/override.yml -e dev_mfapanel=true -e env=vkcloud ../ansible-openstack/playbooks/xaas-add-app-to-catalog.yml
   ```
   По умолчанию все приложения будут опубликованы в дефолтный брокер. Чтобы изменить, задайте следующие параметры:
   
   * `xaas_default_provider.name` — имя брокера поставщика.
   * `xaas_default_provider.token` — токен поставщика для загрузки сервисных пакетов.

   Если необходимо создать нового поставщика во время запуска плейбука загрузки приложений:

   * `xaas_default_provider.name` — имя поставщика.
   * `xaas_default_provider.token` — токен поставщика для загрузки сервисных пакетов (сгенерируйте и сохраните значение токена).
   * `xaas_default_provider.email` — почта, на которую будет зарегистрирован поставщик. На этот ящик будут отправляться уведомления о неудачных попытках заказа приложений и прочие уведомления.
   * `xaas_default_provider.test_ns` — имя тестового спейса данного поставщика, куда будут загружаться приложения. Обычно формат имени `test_ns_<ИМЯ_ПОСТАВЩИКА>`.
   * `xaas_default_provider.prod_ns` — имя пространства, в которое будут публиковаться приложения поставщика. Обычно `vkcs_ru` (пространство, доступное всем пользователям {var(sys2)}).


Чтобы добавить и опубликовать новую версию сервиса в Marketplace c помощью плейбука:

1. Выполните вход на деплой-ноду по SSH (подробнее — в разделе {linkto(../../../interfaces_access#deploy_host_auth)[text=%text]}).

1. Укажите новую версию дистрибутива приложения в поле `distr` в файле `~/inventory/vkcloud/group_vars/vkcloud_control_plane/xaas-apps.yml`.

1. Убедитесь, что значение параметра `install = true`.

1. Если необходимо, чтобы приложение было опубликовано, задайте значение `promotion = true`.

1. Запросите дистрибутив приложений и вручную добавьте его в `{{xaas_distrs_path}}/catalog` (по умолчанию это `~/xaas/catalog`). Файл дистрибутива должен иметь имя `<значение поля distr приложения из файла xaas-apps.yaml>.tar.gz`. Если новый дистрибутив приложения поставляется в составе дистрибутива {var(sys2)}, задайте значение параметра `nexus_source = true`, в других случаях — `nexus_source = false`. 

1. Запустите Ansible playbook:

   ```console
   $ cd ~/inventory/vkcloud 
   $ ansible-playbook -i vkcloud.yml --diff -e @/home/centos/override.yml -e dev_mfapanel=true -e env=vkcloud ../ansible-openstack/playbooks/xaas-add-app-to-catalog.yml
   ```

Новая версия приложения будет загружена в каталог и опубликована в открытое пространство вместо предыдущей. Предыдущая версия будет перенесена в тестовое пространство.
