{ifdef(box, pg)}
При входе пользователя в {var(sys4)} средствами Подсистемы управления доступом выполняется поиск соответствующей учетной записи в собственном хранилище. Если учетная запись не найдена, поиск продолжается в преднастроенных внешних базах данных. Вход в {var(sys4)} разрешается, если учетная запись пользователя найдена.

Управление пользователями выполняется через Портал управления доступом (Keycloak).

Инструкции по выполнению операций с пользователями приведены в [официальной документации Keycloak](https://www.keycloak.org/docs/latest/server_admin/#assembly-managing-users_server_administration_guide).
{/ifdef}

При входе пользователя в {var(sys4_go)} средствами Подсистемы управления доступом (ПУД) выполняется поиск соответствующей учетной записи в преднастроенных внешних базах данных (LDAP-провайдер). Вход в {var(sys4_go)} разрешается, если учетная запись пользователя найдена.

## {heading(Добавление LDAP-провайдера)[id=users_management_add_ldap_provider]}

<!--- #todo на раздел есть ссылка в ПМИ Private Cloud. -->

<warn>

В случае недоступности LDAP-сервера и неработоспособности настроенной федерации пользователей, вход в Портал администратора и Портал самообслуживания будет недоступен как для пользователей LDAP, так и для локальных Keycloak пользователей.

</warn>

Чтобы добавить LDAP-провайдера в Портале управления доступом Keycloak:

1. Перейдите в пункт меню **User Federation**.
1. В выпадающем списке **Add new provider** выберите пункт **ldap**.
1. Задайте параметры подключения к LDAP-провайдеру:

   * **Console display name** — имя LDAP-провайдера.
   * **Vendor** — LDAP-провайдер, который используется в вашей сети. Если вы используете `FreeIPA`, выберите `Rad Hat Directory Server`.
   * **Connection URL** — URL для соединения с LDAP-провайдером. Пример: `ldap://10.28.227.59/`. Нажмите кнопку **Test connection**, чтобы убедиться, что связь с сервером установлена.
   * **Bind Type** — укажите значение `simple`.
   * **Bind DN** — учетная запись пользователя, которая будет использоваться для доступа к LDAP-провайдеру. Пример: `CN=Administrator`, `CN=Users`, `DC=test`, `DC=local`. Учетная запись должна иметь права администратора.
   * **Bind Credential** — пароль учетной записи, которая будет использоваться для доступа к LDAP-провайдеру. Нажмите кнопку **Test Authentication**. Если результат — `Success`, настройка выполнена успешно.
   * **Edit mode** — режим редактирования:

      * **READ_ONLY** — пользовательские данные будут доступны только для чтения.
      * **WRITABLE** — данные будут синхронизироваться с LDAP-провайдером только по требованию.
      * **UNSYNCED** — пользовательские данные будут импортированы, но не синхронизированы с LDAP-провайдером.

   * **Users DN** — домен пользователей. Пример: `CN=Administrator`, `CN=Users`, `DC=test`, `DC=local`.
   * **Username LDAP attribute** — укажите значение `sAMAccountName`.
   * **RDN LDAP attribute** — укажите значение `cn`.
   * **UUID LDAP attribute** — укажите значение `objectGUID`.
   * **User Object Classes** — укажите значение `person, organizationalPerson, user, inetOrgPerson`.

1. При необходимости задайте параметры на других вкладках.
1. Нажмите кнопку **Save**.

Чтобы настроить присвоение ролей и групп всем пользователям из LDAP-провайдера:

1. Перейдите в пункт меню **User Federation**.
1. Выберите созданного поставщика хранилища, нажав на его название в списке.
1. Перейдите на вкладку **Mappers**.
1. Нажмите кнопку **Create**.
1. Задайте параметры:

   * **Name** — название маппера.
   * **Mapper Type** — тип маппера: `group-ldap-mapper` — маппер по принадлежности к группе (в основном используется только этот тип маппера).

      <info>
     
      Описание остальных доступных типов мапперов приведено в [официальной документации Keycloak](https://www.keycloak.org/docs/latest/server_admin/).
         
      </info>

1. Заполните остальные поля, которые появляются при выборе из списка **Mapper Type**.
1. Нажмите кнопку **Save**.

## {heading(Создание пользователей)[id=users_create]}

<!--- #todo на раздел есть ссылка в ПМИ Private Cloud. -->

{ifdef(box, pg)}

Создание пользователей выполняется в разделе **Users** Keycloak.
Пользователи {var(sys2)} создаются в одной из следующих рилмов (realm):

* `master` — только для учетных записей администраторов {var(sys2)}.
* `mcs_users` — для учетных записей пользователей Портала самообслуживания.
* `mcs_admins` — для учетных записей пользователей Портала администратора.

## {heading(Синхронизация пользователей)[id=users_synchronization]}

В рамках интеграции с LDAP-провайдером:

* Organisation Unit **Users** синхронизируется с рилмом `mcs_users` и содержит учетные записи Портала самообслуживания.
* Organisation Unit **Admins** синхронизируется с рилмом `mcs_admins` и содержит учетные записи Портала администратора.

Схема синхронизации учетных записей приведена на {linkto(#pic_realms)[text=рисунке %number]}.

## {heading(Создание учетной записи администратора)[id=add_superadmin]}

<!--- #todo на раздел есть ссылка в ПМИ Private Cloud. -->

1. Войдите в Портал управления доступом Keycloak:

   1. С помощью любого поддерживаемого веб-браузера перейдите по адресу Портала управления доступом Keycloak.
   1. Перейдите по ссылке **Administration console**, чтобы открыть консоль администратора.
   1. Выполните вход в Keycloak с учетными данными системного администратора {var(sys2)}.

1. Создайте учетную запись администратора {var(sys2)}:

   1. Откройте боковое меню и выберите рилм `mcs_admins` в выпадающем списке.
   1. Перейдите на страницу **Users**.
   1. Нажмите кнопку **Add user**.
   1. В поле **Username** укажите имя пользователя в формате электронной почты на домене `vk.team`. Пример: `[test-admin@vk.team](mailto:test-admin@vk.team)`.
   1. Нажмите **Create**.
   1. Перейдите на вкладку **Credentials**.
   1. Нажмите кнопку **Set password**.
   1. В полях **Password** и **Password confirmation** задайте пароль для созданного администратора.
   1. Переведите переключатель **Temporary** в положение `off`.
   1. Нажмите кнопку **Save**.

1. Выдайте права созданному администратору:

   1. Войдите в Портал администратора с учетными данными администратора, созданного при развертывании {var(sys2)} (`superadmin`).
   1. Перейдите в раздел **Управление доступом**.
   1. Нажмите кнопку **Добавить**.
   1. В поле **Логин** укажите имя пользователя, созданного на шаге 2.
   1. В выпадающем списке **Роли** выберите все роли.
   1. Нажмите кнопку **Подтвердить**.

{/ifndef}

## {heading(Управление группами)[id=group_manage]}

{ifndef(cer)}

Инструкции по управлению группами приведены в [официальной документации Keycloak](https://www.keycloak.org/docs/latest/server_admin/index.html#proc-managing-groups_server_administration_guide).

{/ifndef}

С группами доступны следующие действия:

* Создание новой группы.
* Редактирование существующей группы:

   * Добавление атрибутов.
   * Маппинг ролей.

* Добавление в группу или удаление из группы существующих пользователей.
* Настройка групп по умолчанию.
* Удаление группы.

Просмотр списка всех групп доступен в разделе **Groups** Портала управления доступом.

### {heading(Портал администратора)[id=users_list_ui]}

Чтобы посмотреть список пользователей и ролей в Портале администратора:

1. Перейдите в раздел **Управление проектами**.
1. Выберите проект и нажмите на его название.
1. Перейдите на вкладку **Пользователи**.
1. Опционально. Нажмите кнопку **Столбцы таблицы** и настройте отображение списка.

<info>

Чтобы найти пользователя по его почте, используйте строку поиска. При необходимости используйте фильтр по ролям.
Чтобы посмотреть детальную информацию о пользователе, нажмите на его почту.

</info>

Чтобы скачать список пользователей проекта, на вкладке **Пользователи** нажмите на кнопку загрузки и выберите формат выгружаемого файла `.csv` или `.xlsx`.
