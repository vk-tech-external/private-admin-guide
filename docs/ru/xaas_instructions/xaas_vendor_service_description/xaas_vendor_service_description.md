# {appendix-heading(Заполнение описания сервиса для Marketplace)[id=xaas_vendor_service_description; position=prefix]}

Описание сервиса включает:

* Иконку.
* Краткое описание.
* Полное описание.

Описание сервиса задается в его конфигурации.

## {appendix-heading(Иконка)[id=service_description_icon; position=prefix]}

Иконка сервиса отображается в карточке сервиса:

* В каталоге Marketplace.
* На вкладке **Описание сервиса** на странице сервиса.

Для image-based приложения иконка загружается в составе сервисного пакета (подробнее — в разделе {linkto(../../xaas_instructions/xaas_vendor_ibservice_add/xaas_vendor_ib_structure#xaas_vendor_ib_structure)[text=%text]}), для SaaS-приложения — в JSON-файле указывается ссылка на иконку.

## {appendix-heading(Краткое описание сервиса)[id=service_description_short; position=prefix]}

Краткое описание сервиса отображается в карточке сервиса:

* В каталоге Marketplace.
* На вкладке **Описание сервиса** на странице сервиса.

Текст указывается в параметре `short_description` в конфигурации сервиса:

* Для image-based приложения — в файле `service.yaml` из сервисного пакета.
* Для SaaS-приложения — в JSON-файле.

## {appendix-heading(Полное описание сервиса)[id=service_description_full; position=prefix]}

Полное описание сервиса отображается на вкладке **Описание сервиса** на странице сервиса.

Текст указывается в конфигурации сервиса:

* Для image-based приложения — в файле `full_description.md` из сервисного пакета.
* Для SaaS-приложения — в параметре `full_description` в JSON-файле.

В общем случае полное описание сервиса должно содержать следующие разделы:

* Информация о сервисе.
* Правила тарификации.
* Полезные ссылки.
* Техническая поддержка.
* Лицензионное соглашение.

### {appendix-heading(Информация о сервисе)[id=service_description_info; position=prefix]}

В разделе приведите следующую информацию:

* Краткий обзор сервиса.

   Опишите, что представляет собой сервис, какие задачи помогает решать (основные сценарии использования).

* Кто является поставщиком:

   * Вендор.
   * Дистрибьютор.

* Информацию о поставщике (опционально).

   <info>

   Для opensource-решений информация о поставщике не указывается.

   </info>

* Характеристики сервиса. В таблице укажите:

   * Тип сервиса:

      * Image-based.
      * SaaS.

   * Версию сервиса (при наличии). Пример: Usergate 7.01.

      <info>

      Версия сервиса не является ревизией сервиса, указанной в его конфигурации.

      </info>
     
   * Для image-based приложения — конкретную версию ОС. Пример: Ubuntu 22.04.
   * Категорию сервиса. Примеры категории:

      * Аналитика.
      * Базы данных.
      * Безопасность.
      * Инструменты для разработки.
      * VPN.


Для image-based приложения в разделе укажите дополнительную информацию:

* Варианты развертывания сервиса:

   * Одна ВМ.
   * Кластер.

* Какая инфраструктура {var(sys2)} используется. Примеры: ВМ, виртуальные сети.

Чтобы сформировать у пользователя полное представление о сервисе, добавьте в раздел схемы сервиса и скриншоты интерфейса (опционально).

### {appendix-heading(Правила тарификации)[id=service_description_tariff_rules; position=prefix]}

В разделе приведите следующую информацию:

* Тип тарификации (подробнее — в разделе {linkto(../../xaas_instructions/xaas_vendor_index#xaas_billing)[text=%text]}).
* Если сервис имеет несколько тарифных планов, то укажите, что ознакомиться с ними можно в матрице тарифных планов на странице сервиса.
* Если сервис имеет платные тарифные опции, то укажите, что такие опции тарифицируются дополнительно к стоимости тарифного плана.
* Если сервис имеет тарифные планы с договорной ценой, то укажите информацию об этом.
* Для image-based приложения укажите, что стоимость инфраструктуры {var(sys2)} тарифицируется отдельно.

<err>

Если image-based приложение использует инфраструктуру {var(sys2)}, объем и стоимость которой невозможно определить на момент подключения сервиса, например хранение накапливаемой по мере работы информации — резервные копии, сообщите об этом в описании правил тарификации.

</err>

{caption(Пример заполнения раздела с правилами тарификации, формат Markdown)[align=left;position=above]}
```markdown
# Правила тарификации
Сервис предоставляется по модели Bring Your Own License. Тарификация осуществляется только за потребляемую инфраструктуру Private Cloud. Ее стоимость можно оценить в блоке **Детализация** в мастере конфигурации тарифного плана. Итоговая стоимость будет отображена на последней странице мастера конфигурации тарифного плана.
```
{/caption}
